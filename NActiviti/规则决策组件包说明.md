# 规则决策组件包说明

本说明文件适用于以下组件包：

- `Sys.Bpm.Rules.API`
- `Sys.Bpm.Rules.Core`
- `Sys.Rules.DmnEngine`
- `Sys.Rules.DmnEngine.Adapter`

## 组件定位

这些组件为 `nactivity` 提供规则决策运行时、治理仓储、DMN 执行内核与适配层能力，面向工作流编排场景，不单独构建为大型规则平台。

## 包职责

- `Sys.Bpm.Rules.API`：定义决策运行时契约、核心 DTO 与宿主侧调用接口。
- `Sys.Bpm.Rules.Core`：提供规则定义、版本、审计日志等基础设施实现。
- `Sys.Rules.DmnEngine`：提供 Fork 后收口的 DMN 执行内核。
- `Sys.Rules.DmnEngine.Adapter`：提供 DMN 内核与运行时契约之间的适配与依赖注入入口。

## 发布约束

- 相关包应以同一版本号批次发布。
- 禁止只升级内核包而不同步发布契约包。
- 宿主项目应优先通过 `PackageReference` 方式统一引用整批组件。

## 批次打包

- 统一版本入口位于 `NActiviti/Directory.Build.props` 的 `RuleDecisionPackageVersion`。
- 推荐通过 `NActiviti/scripts/pack-rule-decision-packages.ps1` 执行批次打包。
- 推荐通过 `NActiviti/scripts/publish-rule-decision-packages.ps1` 生成正式发布前目录。
- 默认输出目录为仓库根目录下的 `artifacts/packages/rules`。
- 脚本会为每个项目使用独立 staging 目录，只保留目标规则包，不把引用链中的其他包混入最终批次目录。
- 脚本完成后会额外生成 `rule-decision-packages.manifest.txt`，用于记录版本、时间与产物清单。
- 示例命令：

```powershell
.\scripts\pack-rule-decision-packages.ps1 -Version 1.0.1 -OutputPath artifacts\packages\rules -Clean
```

```powershell
.\scripts\publish-rule-decision-packages.ps1 -InputPath artifacts\packages\rules -OutputPath artifacts\packages\publish-ready -Clean
```

- 默认会统一产出以下包：
  - `Sys.Bpm.Rules.API`
  - `Sys.Bpm.Rules.Core`
  - `Sys.Rules.DmnEngine`
  - `Sys.Rules.DmnEngine.Adapter`

## 使用建议

- 宿主应优先通过依赖注入接入 `IDecisionExecutionService`、`IDecisionGovernanceService` 与 `IDecisionCatalogService`。
- 生产环境建议同时配置决策定义仓储、版本仓储与执行日志仓储。
- 若使用 PostgreSQL 或 SQL Server，请确保相关规则表结构与对应 `SmartSql` 映射已同步部署。
- `DecisionRulesStore.configPath` 为空时会按数据库类型自动选择默认值：
  - PostgreSQL -> `resources/db/mapping/postgres/rules.mappings.xml`
  - SQL Server -> `resources/db/mapping/mssql/rules.mappings.xml`
