# 前后端多数据库联调回归清单

## 1. 目标

- 验证 `Workspace / DMN Workspace / BPMN Editor` 在 PostgreSQL 与 SQL Server 宿主场景下，能够正确消费后端 `schema-status` 与规则扩展能力。

## 2. 通用前置条件

- 后端宿主已按目标数据库完成 `7000 -> 7001` 升级。
- 已能正常调用：
  - `GET Api/v1/workflow/process-deployer/schema-status`
  - 决策目录查询接口
  - 决策版本查询接口
- 前端构建已通过：

```powershell
npx tsc -p tsconfig.app.json --noEmit
```

## 3. Workspace 回归

- 打开工作台首页，确认全局风险提示可正常渲染。
- 校验提示信息至少包含：
  - `状态`
  - `数据库类型`
  - `期望版本`
  - `实际版本`
  - `建议`
- 在 PostgreSQL 场景下应显示 `PostgreSQL`，在 SQL Server 场景下应显示 `SQL Server`。
- 当后端返回 `UpgradeRequired` 时，应显示升级提示而非静默隐藏。
- 当后端返回 `InspectionFailed` 时，应显示错误提示而非空白。

## 4. DMN Workspace 回归

- 打开任意决策工作区，确认 schema 状态卡片加载成功。
- 校验数据库类型显示名称为：
  - `PostgreSQL`
  - `SQL Server`
- 校验不同状态的文案：
  - `Healthy`：摘要包含数据库名称与当前版本
  - `UpgradeRequired`：摘要包含数据库名称、期望版本、实际版本、缺失表
  - `InspectionFailed`：摘要包含错误信息
  - `Skipped`：摘要回退为后端 `recommendedAction`

## 5. BPMN Editor 回归

- 打开包含 `BusinessRuleTask` 的流程。
- 当后端返回风险状态时，风险条应展示：
  - `状态`
  - `数据库类型`
  - `期望版本`
  - `实际版本`
  - `建议`
- 部署前确认框与保存前确认框应显示可读数据库名称，不应回退为原始 `postgres` / `mssql` 标识。
- 风险任务点击定位、字段高亮、自动候选补齐、自动版本补齐、完成态回写均应保持正常。
- SQL Server 场景下不得出现“当前不是 PostgreSQL”之类旧文案。

## 6. 联调通过判定

- Workspace 正常显示多数据库 schema 状态。
- DMN Workspace 状态卡片显示正确数据库名称与摘要。
- BPMN Editor 风险条与保存/部署前门禁口径一致。
- PostgreSQL / SQL Server 场景下均无旧 PostgreSQL 专用文案残留。
