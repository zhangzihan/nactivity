# 规则决策治理与审计接口示例

- 日期：2026-07-07
- 适用范围：`nactivity` 当前已落地的规则治理与审计 REST 接口
- 路由前缀：`Api/v1/workflow/decisions`

## 1. 接口概览

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 保存草稿 | `POST` | `/drafts` | 保存或更新决策定义草稿与草稿版本 |
| 发布版本 | `POST` | `/publish` | 将指定版本或当前草稿发布为正式版本 |
| 回滚版本 | `POST` | `/rollback` | 将历史版本重新发布为当前生效版本 |
| 查询执行日志 | `POST` | `/execution-logs/query` | 分页查询执行日志 |
| 获取日志详情 | `GET` | `/execution-logs/{executionId}` | 获取单条执行日志详情 |

## 2. 操作人回填规则

- 三个治理写接口均支持请求体显式传入 `operator`。
- 若 `operator` 为空，REST 控制器会尝试使用 `Authentication.AuthenticatedUser.Id` 自动回填。
- 若宿主已接入现有安全中间件 `SecurityPoliciesApplicationMiddle`，则通常无需前端重复传入 `operator`。
- 若请求进入控制器时认证上下文为空，则 `operator` 仍可能为空；此时建议由宿主网关或上层应用补齐。

## 8. 使用建议

- 前端设计器或治理后台可将“保存草稿 / 发布 / 回滚”视为同一治理流程的三个原子动作。
- 若宿主已通过认证中间件建立当前用户上下文，前端可不再强制提交 `operator`。
- 执行日志查询建议始终显式传入 `pageIndex` 与 `pageSize`，避免默认分页与页面大小口径不一致。
- 若需要问题追踪，优先以 `executionId` 串联 `BusinessRuleTask` 结果变量、执行日志明细与宿主业务审计记录。
- 当前 `DMN` 合法性校验只发生在“发布 / 回滚”阶段，不阻断草稿保存。
- 若目标版本的 `DMN XML` 解析失败或模型校验失败，接口会返回“发布前 DMN 校验失败”异常，不会写入发布态结果。
