# 规则决策双数据库联调与验证清单

## 1. 目标

- 将规则决策主链从“源码已支持 PostgreSQL / SQL Server”推进到“真实环境已验证可交付”。
- 将剩余工作收敛为固定的联调与验收步骤，避免后续反复盘点。

## 2. 当前已完成基线

- `Rules.Core` 已支持 PostgreSQL / SQL Server 双数据库仓储接线。
- `schema-status` 已支持 PostgreSQL / SQL Server 双数据库检查与返回。
- 启动期规则扩展 schema 告警已支持 PostgreSQL / SQL Server。
- SQL Server 的规则决策扩展表 `create / drop / upgrade step / 手工脚本` 已补齐。
- 旧 PostgreSQL 专用仓储与旧 SmartSql 映射已清理。
- 仓库已提供统一验证脚本：
  - `NActiviti\scripts\verify-rule-decision-stack.ps1`
- 仓库已提供运行期 smoke 脚本：
  - `NActiviti\scripts\test-decision-schema-status.ps1`
- 仓库已提供宿主配置样例：
  - `docs\samples\appsettings.rule-decision.postgres.sample.json`
  - `docs\samples\appsettings.rule-decision.mssql.sample.json`
- 仓库已提供数据库核验 SQL：
  - `docs\samples\sql\postgres-decision-schema-check.sql`
  - `docs\samples\sql\mssql-decision-schema-check.sql`
- 仓库已提供前后端回归清单：
  - `docs\analysis\前后端多数据库联调回归清单-20260708.md`

## 3. 构建环境验证

### 3.1 必做项

- 执行统一验证脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\NActiviti\scripts\verify-rule-decision-stack.ps1
```

- 对运行中宿主执行 smoke 校验：

```powershell
powershell -ExecutionPolicy Bypass -File .\NActiviti\scripts\test-decision-schema-status.ps1 -BaseUrl http://localhost:5000 -ExpectedDatabaseType postgres -ExpectedStatus Healthy
```

- 确认以下项目通过：
  - `Sys.Bpm.Rules.Core`
  - `Sys.Bpm.Engine`
  - `Sys.Bpm.Engine.Tests`

### 3.2 结果判定

- 若失败原因是仓库脏输出残留，应先重新执行脚本中的清理步骤。
- 若失败原因是依赖降级或重复 `AssemblyAttribute`，优先视为构建环境问题，而非规则决策功能回归。
- 若失败定位到 `DecisionRules`、`schema-status`、`DecisionSchemaWarningAdvisor` 相关源码，则视为本主线真实回归。

## 4. PostgreSQL 联调清单

### 4.1 数据库准备

- 执行 `docs\PostgreSQL-规则决策表升级脚本-7000-to-7001.sql`
- 执行 `docs\samples\sql\postgres-decision-schema-check.sql`，确认版本与四张扩展表存在
- 确认以下表存在：
  - `decision_definition`
  - `decision_version`
  - `decision_execution_log`
  - `process_decision_reference`
- 确认 `act_ge_property` 中 `name_ = 'schema.version'` 的记录其 `value_ = '7.0.0.1'`

### 4.2 运行期验证

- 调用 `GET Api/v1/workflow/process-deployer/schema-status`
- 验证返回：
  - `databaseType = postgres`
  - `isPostgreSql = true`
  - `isSqlServer = false`
  - `decisionSchemaChecked = true`
- 发布一个带 `BusinessRuleTask` 的流程，确认 `process_decision_reference` 成功写入。
- 发布 / 保存 / 删除流程后，确认引用索引同步刷新。
- 可使用以下脚本做第一轮 smoke 校验：

```powershell
powershell -ExecutionPolicy Bypass -File .\NActiviti\scripts\test-decision-schema-status.ps1 -BaseUrl http://localhost:5000 -ExpectedDatabaseType postgres -ExpectedStatus Healthy
```
